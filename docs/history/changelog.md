- **변경(`server.ts`만):** `gemini_call`(호출마다 토큰 수와 `cost_usd_est`), `photo_analyzed`(`reused` 포함), `photo_analyze_failed`(`code`만), `limit_blocked`(`code`만)를 PostHog로 보낸다. 단가는 `GEMINI_PRICES_USD_PER_1M` 한 곳. 표에 없는 모델은 원가 null. 이벤트는 서버에서만 나가므로 `/api/event` 허용 목록은 그대로다. ## [2026-10-09 KST] 서재 개수 제한 없애기, 같은 사진을 올린 사람도 자기 서재에 남게
- **배경:** `library.json`은 모든 사용자의 서재 항목을 한 파일에 담는데, `/api/analyze`가 `slice(0, 50)`으로 서버 전체 50개만 남겨 누군가의 51번째 수업이 다른 사람의 가장 오래된 수업을 서재에서 지웠다. 또 같은 사진(같은 교재 키)을 두 번째 사람이 올리면 캐시 재사용 분기가 서재 항목을 만들지 않아, 그 사람 서재에 수업이 안 보이고 `/api/lesson/:key`도 403이었다.
- **변경:**
  - 서재 개수 제한을 없앴다(처음에는 사용자별 50개로 고쳤다가, 사용자 결정으로 제한 없음으로 바꿈). 어떤 항목도 개수 때문에 빠지지 않는다. 늘어나는 속도는 하루 사진 분석 한도(기기당 30장, 전체 100장)가 막는다. 사용자가 많이 늘면 `library.json`을 사용자별 파일로 나누는 것을 검토한다.
  - `libraryRules.ts`(새 파일, 순수 함수): `upsertOwnerRow`(내 같은 키 항목만 갈아 끼움), `canAccessLesson`, `planLessonDelete`.
  - `server.ts`: 서재 항목은 (교재 키, ownerId)마다 하나. 새 분석과 캐시 재사용 모두 내 항목을 넣는다(캐시 재사용은 모델 호출·한도 차감 없음 그대로). `/api/lesson/:key`는 그 키 항목 중 하나라도 내 것이면 연다. `DELETE /api/lesson/:key`는 내 항목만 빼고, 그 키를 가리키는 항목이 없을 때만 폴더를 지운다. `library.json` 읽기-고치기-쓰기를 `updateLibraryAsync`로 한 줄로 세워 동시 요청이 서로 덮어쓰지 않게 했다.
  - `docs/policy/copyright-and-data.md`: 어긋나 보이는 점 두 가지를 새 동작으로 고쳐 씀.
- **그대로:** `/api/library` 응답 모양, `/api/photo/:key`(원래 주인 확인이 없음, `<img>`가 기기 번호를 못 보냄), `/api/report`의 언어 찾기, 한도, 화면 코드. 기존 `library.json`은 그대로 호환된다(옮기기 작업 없음).
- **확인한 것:** 타입 검사·빌드 통과. 규칙 함수 단위 시험 5개 통과(다른 사람·내 항목이 수십 개여도 빠지지 않음 포함). 임시 캐시 폴더로 서버를 띄워 같은 사진 재업로드(다른 기기) → 200·재사용·한도 0 차감·그 사람 서재에 보임, 두 사람 모두 열람 200·제3자 403, 제3자 삭제 403, 한 사람 삭제 뒤 폴더 남고 다른 사람은 계속 열림, 마지막 사람 삭제 때 폴더 지워짐, 5명 동시 재사용에서 항목 5개 모두 남음, 신고 정상.
- **알려 둘 것:** 같은 사진을 다른 사람도 올렸으면 내가 삭제해도 서버의 사진은 남는다. 안내문(`PhotoNotice.tsx`)은 고치지 않았다.
